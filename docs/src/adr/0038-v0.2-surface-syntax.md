# ADR-0038: v0.2 surface syntax — `iter` / `fold` / `unfold` combinator forms

**Status:** Accepted

## Context
The three v0.2 core increments — μ-types by bounded unrolling (ADR-0035),
`iter` (ADR-0036), `fold`/`unfold` (ADR-0037) — landed core-and-interpreter
only. Recursive `type` declarations already parse, but the frozen expression
grammar (ADR-0017) has *no application form*: an `= expr` body is only
names, `id`, prefix `~`, and infix `* + ;`. So no `.thse` program could
mention the new primitives; `fold`/`unfold`/`for` were reserved words in the
spec but (an implementation gap) not even reserved in the lexer. This ADR
adds the minimal surface form that makes the v0.2 combinators writable,
checkable, and runnable end-to-end.

## Decision
Add a **keyword-prefixed application at expression-atom level**:

```text
comb     ::= ("iter" | "fold" | "unfold") atomTy atomExpr
atomExpr ::= lowerName | "(" expr ")" | comb
atomTy   ::= UpperName | lowerName | "0" | "1" | "(" ty ")"
```

- **Both arguments are atoms.** The first is a *type* atom naming the
  counter/spine type; the second is the body iso. A compound body is
  parenthesized: `iter Nat (f ; g)`, `iter Nat (~f)`. This is the smallest
  extension that fits the frozen precedence table: the whole form is an
  atom, so `iter Nat f ; g` ≡ `(iter Nat f) ; g` and `~iter Nat f` is the
  adjoint of the whole iteration — no new precedence level, no ambiguity
  with the infix operators.
- **The counter/spine type is written by NAME**, normally the μ-type from an
  ADR-0035 `type` declaration (`iter Nat f`, `fold BitList g`). Elaboration
  lowers it through the environment, so the ADR-0035 bounded unrolling at
  the env's depth (default `D = 4`) supplies the finite numeral / list-spine
  core type — the depth is *not* written at the use site. Surface
  depth-annotation syntax stays deferred (one knob, one place: the env).
- **Lexer.** `iter`, `fold`, `unfold` become keywords (closing the gap where
  the spec called them reserved but the lexer did not); `for` is lexed as a
  keyword with no production, so using it anywhere is a `T0001` parse error.
- **AST.** One node: `Expr::Combinator(CombKind, Type, Expr, Span)` with
  `CombKind ∈ {Iter, Fold, Unfold}`.
- **Static semantics.** Names checks the type argument as an ordinary type
  reference and the body as an ordinary iso expression. Linearity and
  coverage are clause-level judgments and do not apply to `= expr` bodies;
  the body iso is checked at its *own* declaration, and the combinator form
  itself is total by construction (ADR-0007: the count/spine lives in the
  data).
- **Elaboration.** `iter T f` ⇒ `Iso::iter(lower(T), elab(f))`, and likewise
  `fold`/`unfold`. The result is **gated on the core typing judgment**
  (`theseus_core::type_of`): counter-is-numeral, spine-is-uniform-list,
  body-is-endo / element-match (ADR-0036/0037 error taxonomy). An ill-formed
  combinator is "not elaborated" (the crate's empty-diagnostic sentinel) and
  can never reach eval; promoting that gate to a first-class `T0xxx`
  diagnostic is future work alongside `= expr` body typing in general.

## Consequences
A real program per combinator now runs parse → check → elaborate → eval,
forward and backward, graded by the CLI conformance harness (whole-domain
differential oracle + pinned rows + `# fuel-bound` = the ADR-0036/0037
static bounds):

- `conformance/programs/0018-iter-nat.thse` — `iter Nat notb` over
  `Nat * Bit` (flip a bit `k` times, `k` the numeral in the data);
- `0019-fold-parity.thse` — `fold BitList cnot` (reversible parity
  accumulation, spine preserved);
- `0020-unfold-shift.thse` — `unfold BitList swp` (order-sensitive left
  shift through the accumulator, observably the tail-to-head dual of
  `fold`).

`theseus-netlist` still rejects `Iter`/`Fold`/`Unfold` (unchanged — the
loop-node lowering is a later increment).

**`id` as combinator body.** When the combinator is the entire `= expr` body
of an iso with a declared signature (the common case), position type inference
now resolves `id` by extracting the expected body type from the iso's LHS:
for `iter T id` with LHS `T × A`, the body elaborates to `Id(lower(A))`;
for `fold T id` / `unfold T id`, to `Id(elem × lower(A))` where `elem` is
the spine's element type. This covers `iter Nat id`, `fold BitList id`, etc.
`id` inside a compound subexpression (`iter Nat (id ; f)`) still requires
general position typing — see below.

**First-class combinator diagnostics.** Ill-formed combinators now produce
structured `T06xx` error codes (T0601–T0606) with the combinator's span,
mirroring the core typing errors (ADR-0036/0037 taxonomy), instead of the
generic "not elaborated" sentinel.

General position type inference for `id` inside arbitrary `= expr`
subexpressions (e.g. `id ; f`, `id * f`, `iter Nat (id ; f)`) remains
deferred — it requires threading expected types through `elab_expr`
recursively, which is a larger change touching the whole expression
elaboration pipeline.

## Alternatives rejected
General juxtaposition application (`f x`): a much larger change to the
frozen ADR-0017 grammar (currently juxtaposition exists only inside
patterns), for no v0.2 need — the three combinators are the only binders of
type arguments. A `for`-style statement form: heavier, and the combinators
are expressions that must compose with `~ ; * +`. Depth annotation at the
use site (`iter Nat@6 f`): splits the truncation knob across call sites and
contradicts ADR-0035's env-owned depth; revisit only when a program needs
two depths of the same type.
