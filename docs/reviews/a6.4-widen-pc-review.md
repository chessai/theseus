# A-6.4 widen-PC — adversarial review (fresh context, cross-model)

**Scope:** branch `widen-pc` @ `546924e` (off `f186563`), worktree `/tmp/widenpc`.
W_PC 8→16 (PC_hi appended at field 22, STATE_BITS 176→184), W_BR stays 8 with
sign-extended δu, narrow-A fetch, pc_add_br/pc_inc via the TK adder over 16 bits.
Reviewer did not write the change. READ-ONLY: probes run via an external crate
(`/tmp/pcprobe`) with path-deps on the worktree; no worktree source edits.

**VERDICT: NOT SOUND TO MERGE — one hard BLOCKER (the fast gate is red at the
tip: three bveq_netlist tests fail because the symbolic state builders were not
widened), one BLOCKER-class guard gap (forward skip-blocks with body 128..255
silently mis-jump BACKWARD under sext), and one latent MAJOR (fetch predicate
chain corrupts at A_fetch=16, rom_len ≥ 32769, with no guard).**
The core arithmetic (sext δu, split-field TK adder, narrow-A fetch at a ≤ 15)
is verified correct, including exhaustively; the deferral of the OOM ring/energy
tests is sound *in principle* (§5) — but the three findings above must be fixed
(each with its reproducing regression test, per L20) before merge.

---

## Attack 1 — sign-extension of δu + the iter_len ≤ 128 guard

**Backward jumps (δu): PASS.**
`δu = 256 − iter_len` (compile.rs:3797) is minted byte-identically to the 8-bit
design; `pc_update` / `pc_add_br` compute `PC += sext(BR) + 1 (mod 2^16)`.
For `iter_len ∈ [1, 128]`, `δu ∈ [128, 255]` has its top bit set, so
`sext(δu) = δu − 256 = −iter_len` exactly, and
`PC_next = (Ltop + iter_len − 1) − iter_len + 1 = Ltop` — the mod-256 semantics
carry over verbatim. Boundary `iter_len = 128 → δu = 0x80 → sext = −128`:
correct (lands exactly on Ltop). The halt orbit (`rh = 0xFE`, ADR-0034 D5) is
also preserved: `sext(0xFE)+1 = −1` ≡ the old `0xFF mod 256` per-step walk, so
no re-derivation was needed with W_BR unchanged — correct.

**The guard: correct and a single choke point.**
`iter_len > (1 << (W_BR−1))` (compile.rs:3778) rejects exactly `iter_len ≥ 129`
— exactly the set where `sext(δu)` turns positive (iter_len=129 → δu=127 →
sext=+127 → forward = broken). All four δu-mint sites (compile.rs:3818/3831/
3855/3874) sit *after* this guard inside `lower_trace`; there is no other δu
producer. Graceful `Deferred` reject, not corruption. PASS.

**Forward branches: FINDING-1 (BLOCKER-class guard gap) — see Attack 6.**
Legitimate forward offsets ≤ 127 sign-extend to themselves and work. But the
compiler *mints forward offsets up to 255* and nothing rejects 128..255 —
concrete counterexample under Attack 6.

## Attack 2 — the 16-bit TK adder + inter-byte carry

**PASS, exhaustively.** Ran (release, `--features heavy-tests`):

- `adr0034_split_add_exhaustive` — all 2^16 PC × 2^8 BR = 16.7M cases of
  `(pc_add_br ; pc_inc) == PC + sext(BR) + 1 (mod 2^16)` — **green** (~64s).
- `pc_inc_exhaustive_all_16bit` — all 2^16 PCs, full-state equality including
  the 0x00FF→0x0100 and 0xFFFF→0x0000 carries — **green**.

No (pc, br) with a wrong split-field carry exists. The materialize-op/TK-add/
uncompute structure preserves BR (control-only) and restores s0/s1 on the
sampled full-state checks.

*Test-strength note (MINOR-1):* the exhaustive test asserts only `got.pc`; full
state equality (s0/s1/BR/regs) is asserted only on the 8/16-point sampled sets.
A data-dependent scratch leak at an unsampled (pc,br) would most likely bend a
subsequent pc and still be caught, but asserting `got == expected-with-pc` in
the exhaustive loop is cheap and closes it.

*Test-gap note (MINOR-2):* no real-`system_step` test executes a **backward
jump from PC > 256** (the payoff crosses 254→260 with BR=0 only; loop programs
run below 256). The iso-level exhaustive covers the composite `pc_add_br;pc_inc`
which *is* the datapath A-phase, so this is corroboration, not a hole.

## Attack 3 — narrow-A fetch

**Correct for A_fetch ≤ 15; FINDING-2 (MAJOR, latent) at A_fetch = 16.**

Correctness verified for the design range: `fetch_addr_bits(rom_len)` =
⌈log₂ rom_len⌉ clamped to [1,16]; every entry address < rom_len ≤ 2^A_fetch is
distinct in the low bits; PC ∈ [rom_len, 2^A_fetch) matches no entry (parks);
PC ≥ 2^A_fetch fails the shared high-zero gate (parks, no aliasing). Probed at
the worst in-range case a = 15 (rom_len = 32768, entry at 0x7FFF): exact fetch,
neighbors and 0x8000/0xFFFF park — **green** (probe C).

**FINDING-2:** at `a = 16` (rom_len ≥ 32769 — admitted by `assemble`'s
2^16 cap and by `fetch`'s own assert) the per-entry predicate AND-chain
overflows its scratch: `pc_pred` chains `a+1 = 17` controls through
`fetch_chain(0..=14)`, and `fetch_chain(14) = FETCH_S1 + 1 + 6 = wire 63 =
FETCH_HZ_WIRE` — the chain intermediate lands **on the shared high-zero bit**
(which `pc_high_zero(16)` has just set to 1). The 14-slot chain budget
(s0 bits 0..8 + s1 bits 1..7) was sized for the *hz* AND (≤ 15 inputs, 14
intermediates) but the *pred* AND at a=16 needs 15 intermediates. The predicate
inverts. **Real counterexample (probe B, rom_len=32770, word at 0x8000):**

```
pc=0x8000: IR=0x00000000 (expected 0x0eadbeef)  ** WRONG — exact match NOT fetched **
pc=0x8001: IR=0x0eadbeef (expected 0x00000000)  ** WRONG — non-match FETCHED **
```

Reversibility is unaffected (sym still uncomputes) — this is pure fetch
corruption. Unreachable for every current program (ROMs are ≤ a few hundred
words) but there is **no guard**: `fetch` must either reject rom_len > 32768
(one assert; the honest minimal fix, mirroring the iter_len guard's
philosophy) or widen the chain space. The asm.rs doc-comment ("a per-ROM
structural limit checked at fetch-build time", asm.rs:410) claims a check that
**does not exist** — fix the comment or make it true.

*Scratch collision otherwise:* clean. s0‖s1 give 14 chain slots; hz uses ≤ 14
(a=1 worst case, ends at s1 bit 6); pred uses ≤ 13 for a ≤ 15; pred wire (s1
bit 0) and hz wire (s1 bit 7) are skipped by `fetch_chain`. hz is computed
once, wraps all entries, and is uncomputed by `Iso::sym(hz)`; per-entry chains
are restored by `Iso::sym(pred)`.

## Attack 4 — state layout / STATE_BITS 184

**PASS in the datapath; FINDING-3 (BLOCKER) in the BVEQ symbolic builders.**

- Derived constants verified by running the crate: `NUM_CPU_FIELDS = 23`,
  `STATE_BITS = 184`, `PC_FIELDS = 2`, `BR_FIELDS = 1`. Append keeps r0..r7,
  PC_lo(8), BR(9), IR(10..14), s0..s7(14..22) stable; PC_hi = 22;
  `mem_field(i) = 23+i` re-bases automatically. The operand crossbar routes
  only over reg ∪ scratch (16 locations, s0/s1 excluded) — PC_hi is not
  operand-addressable, so no instruction can name it. encode/decode/
  encode_composite/decode_composite/encode_system all push/read PC_hi via one
  helper (`read_pc_bits`); round-trips exercised by every green datapath test.
  `ring_run.rs` frame widths derive from `STATE_BITS` (constants, asserted
  loudly at build).

- **FINDING-3 (BLOCKER — the fast gate is RED at 546924e):**
  `bveq_netlist::build_cpu_init` (src/bveq_netlist.rs:443) and
  `build_system_init` (:483) still build **22** CpuState fields — the appended
  PC_hi field was added only to `build_concrete_system_sv` (:527). The
  symbolic SV shape no longer matches `state_ty()` (23 fields), so the BVEQ
  netlist walk dies with `DomainError("Times: expected Pair")`. **Reproduced:**
  `cargo test --release -p theseus-tisc --test bveq_netlist` (default
  features, the *fast* tier):

  ```
  branch 546924e: bveq_netlist_negative_addi_symbolic_s0  FAILED
                  bveq_netlist_negative_xor_vs_add        FAILED
                  bveq_netlist_walk_reconcile             FAILED
  base   f186563: all four PASS (34s)
  ```

  This is the BVEQ *equivalence trust core* walk — the thing that recognizes
  emitted instructions — silently un-runnable, and it means the branch was
  never gated on the plain fast suite. Fix = append the PC_hi const-0 (resp.
  concrete) field in both builders (and audit `extract_field(_, i, NUM_CPU_FIELDS)`
  consumers for the 23-field shape).

- MINOR-3 (docs): types.rs:127 and :204 say `NUM_CPU_FIELDS ... = 24`; the
  code evaluates to **23**. Off-by-one doc error only. ring_run.rs:480/582
  comments still say "160 + 24 = 184" (pre-A-0 widths); code is derived and
  correct.

## Attack 5 — the deferred ring/energy tests: is the deferral SOUND?

**Yes — deferral is sound in principle, with the evidence below; it is NOT a
license for FINDING-3, which is in the *fast* tier and red.**

What is deferred: `me_a3_golden` (absolute step_j pin) and four ctx()-based
`ring_run` tests (balanced-ring run==eval^R, ancilla restore, area, boundary),
all of which OOM because `lower_iso`/`balance()` intermediates grow with
STATE_BITS (confirmed fundamental; pending lean-lower_iso — design §8 risk 5
called this before implementation).

Why no reversibility/closure hole hides behind them:

1. **Bijectivity of the step at the new width is mechanized, not assumed.**
   The A-phase re-proof is the exhaustive split-add sweep (green, above);
   translation on Z/2^16 is a bijection at any width; E stays keyed on PC and
   PC-preserving (narrow fetch changes the predicate, not the invariant).
   ADR-0034's amendment states exactly this and cites the right witness.
2. **Zero-garbage is structural, not statistical.** Every new scratch use is a
   compute/uncompute bracket at the iso level (`Iso::seq(x, …, Iso::sym(x))`
   for hz and pred; explicit reversed unbuild for the adder operand, whose
   preservation the TK adder guarantees algebraically and the exhaustive sweep
   witnesses). No new cell kinds enter the netlist (still ≤ K2/K3 + R1), so
   `balance()`'s K0-buffer accounting is untouched in kind.
3. **A ring-level witness at the wider state DID run:** the two-body timing
   certificate re-pin (d_pre 2931 / d_post 573 / period 3544,
   `validate() == Ok`) exercises real lowered cpu_pre/mem/cpu_post netlists
   with the bus threaded across the 184-bit carrier —
   `ring_two_body_timing` re-run green in this review (below). That is a real
   composite-ring lockstep check that fits memory.
4. **The real datapath crosses the widened boundary:** `widen_pc_payoff`
   (green, below) runs the real `system_step` 254→260 with terminal
   BR=s0=s1=0 quiescence (the park witness), equal to the fast-sim.

Residual risk after deferral: the *balanced*-netlist ancilla plumbing at 184
bits and the absolute energy pins. Both are width-mechanical, both have
memory-fitting proxies green, and the cell-count deltas (+193 on ~4846,
~0.5%/bit) were measured in isolation. Re-pin `me_a3` when lean-lower_iso
lands, as the `#[ignore]` strings already commit to. Sound.

## Attack 6 — bounds enforcement (iter_len ≤ 128, skip distance, fetch bits)

- `iter_len ≤ 128`: **enforced, graceful, correct** (Attack 1).
- `B + S_max ≤ 2^16` (P2) and per-Trace WCET ≤ 2^16: enforced
  (`p2_guard_lifted_to_16bit` green; rejects at the boundary before any eval).
- Narrow-fetch live-address bits: **NOT enforced** — FINDING-2 (silent
  corruption at rom_len ≥ 32769, no reject anywhere).
- **Forward skip distance: NOT enforced — FINDING-1 (BLOCKER-class).**
  `emit_skip_block` (compile.rs:966) rejects only `body > 255` (:973) and
  mints `BR = body_len` via `Addi` (:989/:1003). Under sext, every
  `body_len ∈ [128, 255]` is a *negative* offset: the "skip" jumps backward
  into the park zone and the machine then walks back *into the ROM* and
  executes garbage. These lengths were **correct under the 8-bit PC** (mod-256)
  and are exactly the arm sizes the A-6 word-synth roadmap is about to
  produce; five call sites feed it (guarded-g :2672, iter :3277, Plus arms
  :4054/:4139/:4145). **Real counterexample (probe A):** hand-assembled
  skip-block shape with body 130 —

  ```
  pc_update(1, 130) = 0xff84          # 8-bit semantics landed at 132 (close Swapbr)
  after 10 steps:   pc=0xfb9c br=0x82 # wandering the park zone backward
  after 2000 steps: pc=0x2fee r2=3    # body executed 3 times — it was to be SKIPPED
  ```

  Fix = reject `body_len > 127` in `emit_skip_block` (mirror the iter_len
  guard; same one-line shape, same `Deferred` error), with a regression test
  that compiles a >127-instruction arm and asserts the reject (and, per L20, a
  ROM-level test like probe A that fails without the guard).

## Bottom line

The load-bearing decision — sign-extending an 8-bit BR into a 16-bit PC so the
entire δu/come-from machinery ships unchanged — is **correct and exhaustively
proven** for everything the compiler currently emits, and the deferral of the
OOM ring/energy goldens is sound. But the branch is **not mergeable as-is**:
the fast gate is red (F-3, a two-function fix), and the same sext decision
that made backward jumps free silently halved the forward-skip reach without
its guard (F-1, a one-line fix) — the exact class of "widen half the invariant"
bug this review exists to catch. F-2 deserves the one-assert guard now, while
the 14-slot chain limit is fresh. Fix all three, each with its reproducing
regression test (L20), re-run the fast + heavy gates, then merge.
