# Adversarial review — M-D.d design (`Trace` as reversible while-loop)

**Reviewed:** `docs/scratch/mdd-design.md` against `interp.rs:163-183`, `compile.rs` (emit_skip_block 595-676, lower_data_dependent_iter 1413-1461, sum layout 61-168, assoc lowering 1380-1393), `step.rs` (SWAPBR/pc_add_br), ADR-0034/0007, and the M-D.w implementation on unmerged branch commit `526b453` (`wcet`, `run_rom_on_cpu`, `max_skip_distance` at compile.rs:1741-1842 of that commit — note: M-D.w is **not on `chessai/theseus-v2` HEAD yet**; mdd's "depends on M-D.w being merged" is currently unsatisfied).

## (A) VERDICT: **DO-NOT-SHIP as drawn — NEEDS-REVISION, not fundamental redesign.**

The §2 pseudo-ROM is broken two independent ways (findings 1, 2): the come-from witness is never cleared and hijacks BR on the second backward re-entry, and `ctrl` leaks across every taken branch. **However, the backward-SWAPBR + come-from architecture itself is sound**: a corrected instruction ordering exists (§D below, hand-verified over 3 iterations) that is a direct application of ADR-0034 D5's join-dispatch discipline. Separately, the design carries a **new BLOCKER the doc did not ask about**: `k_max = |u|` is off by one (finding 3), and the failure it causes passes every P1/P3 guard silently.

## (B) Findings

**F1 — BLOCKER. The §2 loop as drawn: the come-from witness accumulates and hijacks control on the 2nd backward re-entry.**
Evidence: hand-trace in §D. `Ltop: SWAPBR rc` captures δ into rc on re-entry (ADR-0034 D1: BR↔rc; step.rs:34-44 `PC += BR+1`), but §2 contains **no instruction that clears rc** — the "uncompute" block sits after `Lend`, which the taken path never executes. On the third arrival at Ltop, `SWAPBR rc` swaps the *stale* δ back into BR, and PC jumps to `Ltop + δ + 1` = an address *before the loop* (garbage/prologue). Catastrophic control corruption for any trajectory with t ≥ 3.
Fix: witness must be cleared **at Ltop, per iteration**, dispatched on the comer — see §D. This is literally ADR-0034 D5: "a join with several comers must dispatch on the witness value to clear it — the join enumerates its comers." The two comers (fall-through, backward jump) are distinguished by the tag itself (Right = first entry, Left = re-entry), so the dispatch predicate exists in-data. §2 sketched the JUMP half of D5 and skipped the join half.

**F2 — BLOCKER. `ctrl` is never uncomputed on the taken path; the polarity of every subsequent iteration inverts.**
Evidence: §2 places `<uncompute ctrl>` after `Lend`. On the continue path control leaves at `Lend: SWAPBR rb` with `ctrl = 1` live. At the next bottom, any XOR-style recompute (`ctrl ^= tag; ctrl ^= 1`) starts from 1 instead of 0 and produces the **inverted** predicate: a t=2 trajectory then *takes* the backward branch on the exit iteration and runs the body on a Right-tagged (out-of-domain) value; a t=3 trajectory exits after 2 passes with a Left-tagged value that the epilogue "strips" into garbage. Both produce wrong outputs; the second passes the P1/P3 terminal check (BR=0, s0=s1=0 — rc/ctrl are general registers the check never reads, mdw commit compile.rs:1833-1839).
Fix: don't uncompute before the branch — that's the false circularity the design worried about in §8 Q2. `ctrl` **rides across the jump** and is uncomputed at Ltop from the tag, which is unchanged between the bottom compute and the top uncompute (no body instruction executes in that window). See §D. This is exactly ADR-0034 D5's conditional-branch fine print: "the target's come-from mirrors the same pattern **under the same condition value**."

**F3 — BLOCKER (new; not among the design's §8 questions). `k_max = |u|` is off by one; the true bound is `|u| + 1`, and the under-budget failure is silent.**
Theory: for an exiting trajectory the body is applied to inputs `Right(a), Left(w₁), …, Left(w_{t−1})` (interp.rs:163-183 charges one fuel per application, including the exit application). Injectivity forces the `wᵢ` pairwise distinct, giving `t − 1 ≤ |u|`, i.e. **t ≤ |u| + 1 — attained**. Witness: u = Bool, body = the 3-cycle `R() → L(L()) → L(R()) → R()` on `(1+1)+1` (a bijection); trajectory t = 3 > |u| = 2. ADR-0007's "iteration count ≤ |u|" is wrong as stated (its own TH-1 ledger admits "exact bound still owed" — this is the owed correction). Consequence if shipped as designed: `B = spine + |u|·|iter|` under-runs the maximal-trajectory input by exactly one iteration; the run stops mid-loop where BR = 0 and s0 = s1 = 0 (BR is nonzero only during the two SWAPBR steps), so `run_rom_on_cpu`'s terminal check **passes** and a mid-loop payload unmarshals as the answer. A whole-domain oracle catches it only if the test body actually achieves t = |u|+1 — SwapSum-style bodies (t = 2) never do.
Fix: `k_max = |u| + 1`; amend ADR-0007; ship the 3-cycle witness as the regression test (it is simultaneously the double-re-entry witness for F1 — the single most valuable test program of this milestone).

**F4 — MAJOR. `max_skip_distance`'s consecutive-pairing scan breaks in the presence of the loop pair; if the body may contain forward skip-blocks it can UNDER-count S_max → silent PC wrap.**
Evidence: mdw commit compile.rs:1750-1771 pairs consecutive `Swapbr`s and assumes "skip blocks don't nest." The loop contributes `Swapbr rc … Swapbr rb` at distance ≈ |iter|: (a) with a skip-free body the scanner pairs them and **over**-counts S_max by |iter| — sound but tightens P2 spuriously; (b) with any forward skip inside the body (`[Ltop, innerOpen, innerClose, Lend]`) the scanner mispairs `(Ltop, innerOpen)` and `(innerClose, Lend)`, e.g. T=10, o=11, c=40, E=41 yields S_max = 0 vs true 28 — **undercount** → P2 passes falsely → an input taking the inner skip on its last pass parks past 256, wraps, re-executes `rom[0..]`: exactly the alloc2/MEXCHR-class invisible corruption §8 Q7 asks about.
Fix: stop deriving S_max/wcet by ROM scanning. Compute them **compositionally during lowering** (each emit site knows whether it emitted a forward skip or a loop bracket) and return structured metadata alongside `Vec<Instr>`. A Swapbr's direction is data (the sign of the value ADDI'd into rb), statically invisible to a scanner.

**F5 — MAJOR. The loop-carrier register layout is unspecified, and the canonical-layout invariant is ill-typed as stated when |a| ≠ |b|.**
Evidence: body : `u+a ↔ u+b`; leaf counts are `1 + max(|u|,|a|)` in and `1 + max(|u|,|b|)` out (compile.rs:65-80). If they differ, `homes_in == homes_out` (the compile.rs:1440 pattern) compares vectors of different lengths. The feedback path also silently assumes u's payload occupies the *same physical registers* in both layouts.
Fix (design must state it): the loop carrier is `1 + max(|u|,|a|,|b|)` registers — tag at leaf 0, payload zero-extended to the widest arm (the encoding already zero-pads, compile.rs:147,153) — and the body is lowered once under that ctx with the **loop invariant** `homes_in == homes_out` (a strictly stronger cousin of the 1440 assert: not just "unchanged during lowering" but "output layout = input layout", since PC re-enters the same instructions). With that, feedback of `Left(w)` is layout-exact: tag reg + first |u| payload regs, rest provably 0. Also pin register pressure: the loop consumes 4 dedicated aux (rc, rb, temp, ctrl — all must be *registers*, live across the jump, unpageable) + the tag reg ⇒ ≤ 3 payload leaves stay register-resident before paging; a new `MAX_LEAVES_LOOP` ceiling analogous to MAX_LEAVES_BRANCHING (compile.rs:234) is needed.

**F6 — MAJOR (scope contradiction). The acceptance tests the milestone needs are likely uncompilable under the inner-control policy the design implies.**
The alloc2 precedent (`has_inner_control`, compile.rs:591-593, applied at 1433) rejects Swapbr-containing bodies. If M-D.d inherits it for trace bodies (the safe choice, and the only thing that keeps F4's scanner mispairing unreachable), then **any body containing a Plus with a non-empty arm is rejected** (lower_bare_plus emits skip-blocks, compile.rs:1676-1683) — which excludes §4 A2's "countdown/collatz-style" bodies and possibly the F3 3-cycle witness. The 3-cycle *is* expressible as 4 straight-line instructions (`t ^= p; t ^= 1; p ^= t; p ^= 1` — it's affine over GF(2)²), but no current iso term lowers to that: the structural route `SwapSum ∘ AssocRSum` hits F7. The design must resolve this explicitly: either (a) support exactly one level of forward-skip inside the loop body (semantically fine — inner skips are BR-clean, self-contained, executed fully each pass; the risk is purely allocator reservation + F4 accounting, both fixable with OccSet + compositional metadata), or (b) restrict v1 to Swapbr-free bodies **and demonstrate in the design a compilable t ≥ 3 witness** (e.g. a special-cased/prim lowering). Option (b) without the witness means A1/A2/A5 never exercise the second backward re-entry — the exact case where F1 lives — and the milestone would green-light a broken come-from.

**F7 — MAJOR (latent, pre-existing, now in the blast radius). `AssocLSum/AssocRSum/UniteSum/UnitiSum` lower as unconditional no-ops (compile.rs:1380-1387) but are NOT no-ops in the tag+payload encoding for nested sums.**
Witness: AssocRSum on `(1+1)+1 ↔ 1+(1+1)`: `L(R())` = bytes (0,1) must become `R(L())` = (1,0); the no-op leaves (0,1) → **silent miscompile**, no guard, `Ok(vec![])` unconditionally. Today's programs apparently never compile a non-trivial sum assoc, but Trace carriers are nested sums (`u+a`) and real bodies will assoc-juggle them routinely. M-D.d must either fix or loudly reject non-trivial assoc before trace bodies can be trusted. (Reproducing test: whole-domain oracle on any iso containing `AssocRSum((1+1)+1)`.)

**F8 — MODERATE. `B(rom) == B(sym rom)` (mdw §2/T4) is not structural once loops exist.**
The *semantic* two-direction bound holds (finding in §C Q3), but the numeric equality requires `|compile(body†)| == |compile(body)|`, which nothing guarantees (recognize_prim maps addInto↔subFrom at equal length today, but that's accident, not invariant). Downgrade T4 to per-direction correctness (`each ROM runs within its own wcet`) or prove length-preservation of `sym` per-construct.

**F9 — MODERATE. Practical compilability under the 8-bit PC is a corner, and the design should say so with numbers.**
`|iter| = |body| + 10` (corrected skeleton: 5 top + 5 bottom). P2 requires `spine + (|u|+1)·(|body|+10) + S_max ≤ 256`. Concretely: |u|=2 ⇒ |body| ≤ ~70; |u|=4, |body|=10 ⇒ B ≈ 105 ✓; |u|=8 ⇒ |body| ≤ ~18; |u|=16 ⇒ |body| ≤ ~4; any byte-wide carrier (|u|=256) is unconditionally rejected. So A1/A2 on Bool/Nat@4 carriers fit comfortably, and nothing bigger does: M-D.d is a machinery-proof milestone, and **useful** Traces are gated on a widen-PC ADR. That's acceptable (reject-don't-corrupt, mdw §3.1's honest limit) but should be stated as a §5 non-goal with this arithmetic.

**F10 — MINOR.** (a) mdw P1's audit ("Swapbr emitted only by emit_skip_block") goes stale; re-audit the loop's two new emission sites — fall-through exit leaves BR=0, so P1 survives, but the ledger text must say so. (b) There is **no P3 pairing checker in asm.rs** (ADR-0034 D5 promised one; only range/alias checks exist, asm.rs:202-220) — the loop ships with zero mechanical pairing enforcement; fine for now, note it. (c) §7's budget-threading plan is correct and genuinely needed: the M-D.w implementation hard-codes `budget = instrs.len()` inside `run_rom_on_cpu` (commit 526b453, compile.rs:1806) and never calls `wcet()`. (d) A6: run serialized like the consolidated `mexch_reg` test (OOM precedent).

## (C) Answers to §8 Q1–Q7

- **Q1 (come-from under backward jump): NO as drawn — rc is provably NOT 0 at the next Ltop.** The witness accumulates for exactly one iteration and then swaps back into BR (F1 trace). The forward pair in emit_skip_block works because *one* register plays both roles and the taken path executes *both* SWAPBRs with the constant making a closed circuit (out via BR, back into rb, CSWAP-routed, SUBI-cleared, all under an invariant ctrl). The backward pair splits the roles across rc/rb and §2 never closes the circuit. The repaired scheme (§D) closes it: δ circulates `prologue-ADDI → temp → rb → BR → rc → temp → SUBI` exactly once per iteration — a conserved token — and rc is 0 at every body entry.
- **Q2 (ctrl uncompute vs taken branch): an ordering exists; the circularity is illusory.** Compute `ctrl := ¬tag` *after* the body, branch on it, and uncompute it *at Ltop* from the same tag — the tag cannot change in the window because the only thing between the bottom compute and the top uncompute is the jump itself. On the exit path `ctrl` computes to 0 (`¬Right`), so nothing rides out. On first entry `ctrl = 0 = ¬Right` (prologue injected Right), so the top uncompute (`ctrl ^= tag; ctrl ^= 1` net-XOR of ¬tag) is identity-correct there too. All four cases verified in §D.
- **Q3 (two-direction k):** YES semantically. `(Trace f)† = Trace(f†)` (adjoint.rs:90, same u). If forward runs t applications through `w₁…w_{t−1}`, then `f†` maps `Right(y) → Left(w_{t−1}) → … → Left(w₁) → Right(a)` — exactly t applications; exit condition is "tag = Right" in both directions (reverse enters on `Right(b) : u+b`, exits on `Right(a) : u+a`) — the scheme is direction-uniform. But the *numeric* `B == B(sym)` equality is fragile (F8), and both directions need `k_max = |u|+1` (F3).
- **Q4 (park span):** the arithmetic transfers: parked PC = `B + S` worst-case (minimal-t input takes zero backward jumps, reducing to mdw's monotone derivation), so P2 `B + S_max ≤ 256` is exactly the right guard **provided S_max is computed correctly (F4) and B uses |u|+1 (F3)**. Idle span `(k_max−t)·|iter|` stays in the dead zone by P2. Concrete numbers in F9: |body|≈10, |u|=4 ⇒ B≈105, fine; Trace is compilable only for tiny carriers; anything real needs the widen-PC ADR.
- **Q5 (tag across feedback):** survives **only** under the F5 layout contract (carrier = `1+max(|u|,|a|,|b|)` regs, zero-extension invariant, `homes_in == homes_out` as a hard error, not debug_assert). Unstated in the design; must be added. The 0=Left/1=Right convention (compile.rs:63,145,151) makes prologue = `XORI tag,1` on a fresh zero and `ctrl = ¬tag`, both clean.
- **Q6 (ring/refetch):** structurally sound. Fetch is a stateless XOR mask keyed on PC (step.rs:113-140); P4 re-zeroes IR every cycle, so revisiting an address refetches identically. Bus-quiescence is a per-`system_step` property (emit/mem/absorb close within each cycle, step.rs:259-280), PC-agnostic, hence automatic per-iteration — obligation 6 is free. A6 is feasible (B ≤ 256 revolutions ≪ the 3028-step 2b-lite cert) with the serialized-test/OOM precaution.
- **Q7 (minimal carrier):** u = Bool with the affine 3-cycle body — it exercises t = 3 = |u|+1: two backward re-entries (the F1 crux) *and* the F3 boundary in one 3-input program. SwapSum bodies (t = 2, one re-entry) are insufficient — they cannot distinguish a chaining come-from from a once-working one. Whether the 3-cycle is compilable is exactly the F6/F7 decision the design must make; if it isn't, the milestone cannot test its own hardest property.

## (D) The §2 encoding: does the come-from chain? **NO as drawn / YES as corrected.**

Corrected skeleton (δu = 256−(L+9), L = |body|; tag: 0=Left, 1=Right; all of rc, rb, temp, ctrl are dedicated registers, 0 at program start):

```
prologue: XORI tag,1          ; inject Right      ADDI temp,δu   ; mint token
T   : SWAPBR rc               ; catch: rc ← δu on re-entry, 0 on fall-through
T+1 : CSWAP ctrl, rc, temp    ; join-dispatch: route witness (rc→temp) iff ctrl
T+2 : SUBI temp, δu           ; burn token (both comers now have temp=δu here)
T+3 : XOR ctrl, tag
T+4 : XORI ctrl, 1            ; ctrl ⊕= ¬tag → 0  (tag unchanged since bottom)
T+5 : <body, L instrs>        ; sees rc=rb=temp=ctrl=0
X   : XOR ctrl, tag
X+1 : XORI ctrl, 1            ; ctrl := ¬tag  (1=continue, 0=exit)
X+2 : ADDI temp, δu           ; mint token
X+3 : CSWAP ctrl, temp, rb    ; continue: rb=δu,temp=0 · exit: rb=0,temp=δu
E   : SWAPBR rb               ; continue: BR=δu → PC = E+δ+1 = T · exit: nop
E+1 : SUBI temp, δu           ; burn token (exit path)
E+2 : XORI tag, 1             ; strip Right → tag reg freed to 0
```

Hand-trace, tags (0,0,1), i.e. t = 3: **Iter 1** (fall-through): T nop; T+1 no-swap (ctrl=0); T+2 temp δu→0; T+3/4 ctrl 0→1→0; body → tag=0; bottom ctrl→1, temp→δu, CSWAP → rb=δu; E: BR=δu, rb=0, PC→T. **Iter 2** (re-entry, ctrl=1 in flight): T: BR=δu↔rc=0 → BR=0, rc=δu; T+1 CSWAP fires → rc=0, temp=δu; T+2 temp→0; T+3/4: ctrl = 1⊕0⊕1 = 0. **All aux zero, tag intact, before the body re-runs.** Repeats identically. **Iter 3**: top join clean as iter 2; body → tag=1; bottom: ctrl = 0⊕1⊕1 = 0 (exit); CSWAP no-fire (temp=δu, rb=0); E nop; E+1 temp→0; E+2 tag→0. Terminal: rc=rb=temp=ctrl=BR=0, payload = y. The come-from **chains**: the witness is captured, dispatched on the comer (ctrl = ¬tag), and destroyed within each iteration; nothing accumulates. First-exit (t=1) and t=2 cases verified clean as well. CSWAP distinctness (asm.rs:117) satisfied throughout.

## (E) Solid vs broken

**Solid:** the §1 argument that guarded unroll cannot express Trace (verified against emit_skip_block's cleanup CSWAPs at compile.rs:654-673 — the guard-invariance requirement is real, and the counter-in-data reformulation does *not* dodge it: per-copy guard snapshots are unrecoverable ancillas whose only uncomputation is a Bennett-style reverse pass); loop-not-unroll is the right call spatially too (unroll = k_max ROM copies vs one). The M-D.w foundation transfers: parked-PC = B+S arithmetic, P1/P3, dead-zone idling, §3.2 no-early-stop, §7 budget threading. Ring closure and per-iteration bus-quiescence are free by construction. The one-task decomposition (Trace now, CALL/RET as M-D.d2) is right — the corrected join *is* the shared come-from machinery d2 needs.

**Broken / must change before delegation:** the §2 instruction ordering (F1, F2 — replace with §D or equivalent, and make the 3-iteration chaining trace part of the design); `k_max = |u|` → `|u|+1` + ADR-0007 amendment + the 3-cycle maximal witness in A1/A2/A5 (F3); S_max/wcet must become compositional metadata, not a ROM scan (F4); the loop-carrier layout contract and aux register budget (F5); an explicit inner-control policy that keeps the t ≥ 3 witness compilable (F6); the assoc no-op latent bug guarded or fixed before bodies rely on sum restructuring (F7). Per L20, each of F1–F4 needs a reproducing test that fails under the as-drawn design (the 3-cycle program covers F1 and F3 in one).
