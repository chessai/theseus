# A-6.4 · Widen the PC/budget (B > 256) — DESIGN (draft, on merged A-0)

**Status:** advisor draft, scoped by a read-only code-audit of the merged A-0
worktree (`a6-synth`, branch `a6-synth`). **HIGHEST BAR** — CpuState layout + PC
arithmetic + fetch predicate + the ADR-0034 total-bijection proof; a bug here
silently corrupts *every* compiled program. This supersedes the pre-A-0
`docs/scratch/widen-pc-design.md` (r1), whose layout numbers (NUM_CPU_FIELDS=20,
16-bit IR, s0@field 12) are **stale** after A-0 (now 22 fields, 32-bit IR,
s0@field 14). It is the same change the roadmap calls **A-2 "Coordinated
address-width widen"** (`docs/src/tisc2-roadmap.md:88`), corrected per review
**BLOCKER-3** (decouple `δu` from `B`).

## 0. Why we need it now

The word-level synthesizer (A-6 W, merged 5f8efd0) produces a short-but-not-tiny
reversible body for prims like `gcd2`. The compositional loop budget

    B = spine + k_max · iter_len,   iter_len = |body| + LOOP_OVERHEAD (=10)

exceeds the current **256** cap once such a body sits under a `Trace`. The cap is
not a soft limit — it is the wrap point of the 8-bit PC/BR. Three hard guards
reject `B > 256` today, and past them the fast-sim and the hardware would both
silently wrap `PC` mod 256 (corruption, not an error):

- `compile.rs:2752`  `Trace WCET {} exceeds 256` (per-Trace feasibility).
- `compile.rs:3273`  `budget + s_max_val > 256` → park-unsafe reject (P2).
- `asm.rs:393`       `prog.len() > 256` → `ProgramTooLong` (ROM address space).

**Target B is a measurement in flight** (memory note: gcd2 word body
`peak_work=10`, likely a few hundred to ~2000). The mechanism below is
**parameterized by a target B**; the *minimum-widening principle* (§6) picks the
smallest PC width that fits it.

## 2. Is W_pc already decoupled from N_rom? — **NO. A-6.4 must decouple it.**

**Finding: fully coupled today.** PC width == W == the ROM-address-compare width
== the register width == BR width. Concretely:

- The fetch predicate (`pc_pred`, `step.rs:101`) compares **all W** PC bits, so
  the reachable-PC range and the ROM address space are the same 2^W.
- **narrow-fetch is NOT merged** into A-0 (`grep fetch_a|fetch_addr_bits|pc_pred_a`
  finds nothing in `src`). The r1 drafts `fetch-narrow-compare-design.md` and
  `widen-pc-design.md` were validated as a POC (`fetch_equiv`) but **paused**
  (MEMORY: "Slice A narrow-fetch VALIDATED … but PAUSED pending the design").

**BLOCKER-3 restated in this code:** two different quantities are conflated by the
single width W —
1. **δu = static ROM back-jump offset** (`compile.rs:2763`): its magnitude is
   `iter_len` (a *ROM-length* quantity), and it must fit in **BR** because
   `Swapbr` swaps δu into BR (`compile.rs:2821`). δu scales with **N_rom**.
2. **B = dynamic step count** (`Lowered::wcet`): the number of `pc_add_br;pc_inc`
   cycles PC walks through, capped by P2 at 2^W. B scales with **W_pc**.

They are the same 8 bits today only by accident. A widened design must keep them
**separate axes**: BR must hold the largest δu (∝ log₂ N_rom); PC must hold the
largest reachable step index (∝ log₂ B). For a single flat loop
`N_rom ≈ iter_len` and `B ≈ k_max·iter_len`, so **B > N_rom** and W_pc is the
binding constraint — but a program with many short loops can have small B and
large N_rom, so the design must not assume `W_pc ≥ W_br`.

**Decision:** A-6.4 widens **W_pc** (PC value width) and **W_br** (BR / δu width)
as *independently parameterized* widths, both defaulting to the smallest that fits
their respective bound, and **folds in narrow-A fetch** so the ROM-address compare
costs ∝ ⌈log₂ B⌉ rather than W_pc. This realizes the roadmap A-2 text
(`tisc2-roadmap.md:88-96`) exactly.

## 3. The mechanism (parameterized by target B)

Let `A_pc = ⌈log₂(B + S_max)⌉` (bits to hold every reachable PC: live + parked +
forward-skip), `A_br = ⌈log₂(max δu + 1)⌉` (bits to hold the largest back-jump /
come-from token). Keep the data-word width **W = 8 unchanged** (widening W taxes
every register-arithmetic gate; §5). Both A_pc, A_br ≤ some ceiling W_max chosen
per the target (see §6).

### 3.1 Layout: PC and BR become multi-byte, all-`word8` fields (types.rs)
Keep the uniform `word8()` field layout (minimal type disruption). Add
`⌈W_pc/8⌉ − 1` extra PC bytes and `⌈W_br/8⌉ − 1` extra BR bytes as **appended**
CPU fields (append, not insert, to keep reg/IR/scratch indices stable — the r1
open question resolves to *append*, since no code assumes PC_lo/PC_hi bit
adjacency; the fetch and arithmetic address bytes by field index, not contiguity).
For the likely target (B ≤ 2048 ⇒ A_pc = 11, one extra PC byte; A_br ≤ 8 for a
single short loop, possibly one extra BR byte for large N_rom):

- `NUM_CPU_FIELDS 22 → 22 + n_extra_pc + n_extra_br`.
- `StateVals.pc: u8 → u16` (or u32 if W_pc>16); `br: u8 → u16` likewise.
- encode/decode push/read the extra byte(s); re-derive `mem_field` base and
  `STATE_BITS`/`COMPOSITE_BITS`/`SYSTEM_BITS` from the new field count.
- **Invariant:** only the low A_pc bits of PC (A_br of BR) are ever non-zero on a
  correct program — the P2 bound (now `B + S_max ≤ 2^A_pc`) guarantees it.

### 3.2 PC arithmetic across the byte boundary (step.rs)
`pc_add_br` and `pc_inc` extend from `W` bits to `W_pc` bits, carrying **across the
PC_lo→PC_hi field boundary** (carry out of bit 7 → PC_hi bit 0). The TK
zero-ancilla adder and the ripple increment both extend by the extra bit
positions; the wire layout becomes `n = (n_pc_bytes + n_br_bytes)*W` over the PC
and BR fields. `pc_add_br` adds the (A_br-bit) BR into the (A_pc-bit) PC. Bits
above A_pc stay provably zero (P2). **This is the classic off-by-one risk** — the
mandatory exhaustive test (§7) is `split-field (pc_add_br; pc_inc) == (PC+BR+1) mod
2^A_pc` over all `PC ∈ [0,2^A_pc)`, `BR ∈ [0,2^A_br)`.

### 3.3 Narrow-A fetch (step.rs) — makes the widening nearly free
Replace `pc_pred(addr)`'s full-W AND with an **A-bit** compare over the low
`A_fetch = ⌈log₂(B+S_max)⌉` PC bits (= A_pc), plus **one shared** "high bits all
zero" safety gate (defensive: if violated — impossible on a correct program — no
entry matches, machine parks). Per-entry predicate cost drops from `2(W_pc−1)` to
`2(A_fetch−1)`; the W_pc-dependent term appears **once per step** (the shared
gate), not `N×` per entry. Compiler computes `A_fetch` from `B = wcet` and `S_max`
(both already known) and threads it into `fetch`. The r1
`fetch-narrow-compare-design.md` §7 soundness lever applies verbatim: A_fetch
reuses the *exact* bound P2 already trusts, so it introduces no new trust
assumption. **This is the prerequisite that turns widen-PC from ~+10-15%/bit into
low-single-digit % (§5).**

### 3.4 δu / BR encoding (compile.rs, asm.rs) — the decoupled static offset
- `delta_u` becomes width-A_br (u16 if needed): `(N_rom_span - iter_len) mod
  2^A_br` where the modulus is the **BR** width, not the PC width.
- Minting δu into a register: if A_br > 8, the single `Addi{imm:u8}` (8-bit imm,
  `asm.rs:236`) can no longer load it in one instruction. The I-word already has
  a **20-bit immediate field** (`asm.rs:55 IMM_BITS=20`), so the cheapest fix is
  to **widen `Instr::Addi/Subi{imm}` to the imm width used by δu** and widen
  `decode`'s `word & 0xFF` (`asm.rs:374`) to `word & ((1<<IMM_BITS)-1)` (or to
  A_br bits). No ROM-word format change — only the `Instr` type + decode + the
  `pc_add_br`-style imm handling. (Alternative: mint δu with two `Addi`s
  (`imm_hi<<8 | imm_lo`); avoids widening the imm but costs an instruction per
  loop and complicates the come-from arithmetic — reject unless the imm widen is
  disproportionately risky.)
- `asm.rs:393` ROM-length cap → `N_rom ≤ 2^A_addr` where A_addr = ⌈log₂ N_rom⌉ is
  the ROM address space (independent of B; this is the N_rom axis).

### 3.5 The caps become width-parameterized (compile.rs, energy.rs)
- `compile.rs:2752`  `this_wcet > 2^A_pc` (was 256).
- `compile.rs:3273`  `budget + s_max_val > 2^A_pc` (was 256).
- `compile.rs:3541/3456/3526`  fast-sim PC update widens to `u16`/`u32` matching
  `StateVals.pc` (all three copies).
- `energy.rs:349`, `compile.rs:3449/3521`  dead-zone upper bound `256 → 2^A_pc`.
- `asm.rs:393`  `256 → 2^A_addr`.

All literal `256`s become `1 << W_pc` (or the appropriate width constant). Define
`const W_PC`, `const W_BR`, `const PC_ADDR_SPACE = 1 << W_PC` in one place
(types.rs) and route every cap through them — no scattered magic numbers.

## 4. ADR-0034 injectivity re-proof at the wider width

ADR-0034 D4 proves `step = A ∘ E` is a total bijection on the **full 2^160 state
space** (now 2^STATE_BITS with the wider PC). The proof's structure is
width-**agnostic** — but two clauses name the width and must be re-argued:

1. **`A : (PC,BR,rest) ↦ (PC+BR+1, BR, rest)` is a bijection** (D4 step 4,
   `step.rs:58`). Today this is arithmetic **mod 2^W = mod 256**, and the inverse
   is `PC−BR−1 mod 256`. At width A_pc it is **mod 2^A_pc**, and the inverse is
   `PC−BR−1 mod 2^A_pc`. Bijectivity of `x ↦ x + c (mod 2^k)` holds for **every**
   k (it is translation on Z/2^k), so **A stays a bijection at the new width** —
   provided BR (the added constant per fiber) is *preserved* by A, which the TK
   adder guarantees (BR is the operand, unmodified). **What must be re-argued:**
   that the *split-field* `pc_add_br;pc_inc` computes exactly `(PC+BR+1) mod
   2^A_pc` (the carry crosses the byte boundary correctly and does not leak into
   bits ≥ A_pc). This is the §7 exhaustive test — it is the mechanized form of the
   re-proof.

2. **`fetch` is keyed on PC and preserves PC** (D4 steps 1–3). Narrow-A fetch
   changes the *predicate* (low A_fetch bits + shared high-zero) but not the
   invariant: fetch still writes only IR and s1, still keyed on PC, so
   `PC ∘ E = PC` and `E = ⊕_p E_p` fiberwise. **What must be re-argued:** the
   A-bit compare is **injective on reachable PC values** — i.e. no two reachable
   PC ∈ [0, B+S_max) collide on the low A_fetch bits. Since A_fetch =
   ⌈log₂(B+S_max)⌉ ⇒ 2^A_fetch ≥ B+S_max > every reachable PC ⇒ they are all
   distinct in A_fetch bits. The shared high-zero gate makes the "unreachable
   high PC" case park (no false match) rather than corrupt. (r1 §7 lever.)

3. **The state-space size changes** (2^160 → 2^STATE_BITS) but injectivity is
   proved *without reachability* (ADR-0034 D4 note, `step.rs:60`), so **no
   side-condition is introduced** by the larger space — the argument is
   "A and E are bijections, hence their composition is", which is size-independent.

4. **The HALT orbit** (ADR-0034 D5, `rh` preloaded 0xFE = `2^W−2`): the period-2
   idle orbit uses BR = `2^W_br − 2`. This constant is width-dependent; re-derive
   it for W_br (`0xFE → 2^W_br − 2`) and re-pin the halt-orbit test.

**Re-proof deliverable:** update ADR-0034 (or an amendment ADR) D2/D4/D5 to state
the update is `PC += BR + 1 (mod 2^W_pc)`, cite the exhaustive split-field test as
the mechanized injectivity witness, and re-derive the halt constant. The
*counterexample-dissolution* argument (D4 note) carries over unchanged (the
predecessor PC is still the function `PC'−BR'−1`, now mod 2^A_pc).

## 5. Standing energy cost — the per-PC-bit tax + minimal widening

**Energy model (energy.rs):** `step_j = balanced_energy(step_net)` = active-cell
energy (`compiled_energy`) + analytic K0-buffer energy
(`analytic_buffer_count × k0_per_cell_j`, `energy.rs:88-117`). It is a **static
cell-inventory price**: `total_j = B × step_j` (data-independent, `energy.rs:427`).
So the tax of widening = the extra cells (and their balance buffers) added to the
`step` netlist by the wider PC.

**Where added PC bits add cells:**
- `pc_add_br` + `pc_inc`: each extra PC bit adds ~a constant handful of
  CNOT/Toffoli to the ripple chains (once per step). This is the *unavoidable*
  arithmetic tax and it is small (a few cells/bit on a ~4846-cell step).
- Fetch predicate: with **narrow-A fetch**, the per-entry compare is A_fetch-wide
  (∝ log₂ B), **independent of W_pc**. Only the single shared high-zero gate grows
  with W_pc (once/step). *Without* narrow-fetch, each of N entries would add
  `2·(extra bits)` Toffolis — the `N×` term the memory note's "~+10-15%/bit"
  refers to (the naïve full-W widen). **Folding in narrow-fetch is what collapses
  the tax to low-single-digit %.**

**Estimate (structural, not measured — a measurement is owed before merge):** at
W=8 the step is ~4846 cells; the fetch predicate over N live entries dominates the
PC-dependent cost. The r1 fetch-narrow analysis quantified fib (B=24 ⇒ A=5): 4
Toffolis/entry vs 7 (−43% on fetch predicates). Adding PC bits *with narrow-fetch*
adds only: (pc-arith growth, ~4–8 cells/bit once) + (shared high-zero coverage,
~2 cells/bit once). On a ~4846-cell step that is well under 1%/bit — versus the
naïve `N·2`-per-bit (≈ N/2400 per bit ≈ several % for N~60). **The measurement the
POC owes** (roadmap `tisc2-roadmap.md:54`, r1 §5): `step_j(W=8, A_pc=11, GCD-sized
ROM)` vs `step_j(8-bit PC)` — target delta a few %, dominated by pc-arith, not
fetch.

**Recommended minimal widening for the target B:**

| target B | A_pc = ⌈log₂(B+S_max)⌉ | extra PC bits over 8 | PC field bytes | est. standing tax* |
|---------:|:----------------------:|:--------------------:|:--------------:|:------------------:|
| 512      | 10 (allow S_max slack) | 2                    | 2 (u16)        | ~1–3% (w/ narrow-fetch) |
| 1024     | 11                     | 3                    | 2 (u16)        | ~1.5–4%            |
| 2048     | 12                     | 4                    | 2 (u16)        | ~2–5%              |

*Tax estimate = pc-arith growth only, contingent on narrow-fetch shipping in the
same slice. Without narrow-fetch, multiply by ~N (per-entry) → 2–4× larger.
**Numbers are structural estimates; the POC must measure and re-pin.**

**Minimal-widening principle:** choose W_pc = smallest byte-multiple ≥
⌈log₂(B_target + S_max)⌉. For B up to 2048 that is **W_pc = 16 (one extra PC
byte, u16)** — no case in the plausible target range needs a third PC byte. Keep
W_br at 8 unless N_rom forces δu > 255 (single short loops keep W_br = 8; the
extra BR byte is only paid when a program's ROM span exceeds 256). **Do not widen
past the measured target** — every unused high bit is a permanent tax.

## 7. Slice breakdown for the implementation (follow-up agent)

This is a **highest-bar decoder/state/proof change** → full L15 / L19 / L20 / L21
+ real-authority gates (fresh-context adversarial review by a *different model*; a
reproducing real-worktree behavioral test; every finding ships with a regression
test that fails without the fix). **POC-FIRST** (the one time a hard emission
change skipped POC it failed — r1 §deleg). Commit-only, never push.

**S0 — Narrow-A fetch (prerequisite, cheap, ships value alone).**
Implement `fetch_a(rom, A_fetch)` + `pc_pred_a` (low-A compare + shared high-zero
gate) + `fetch_addr_bits(B, S_max) = ⌈log₂(B+S_max)⌉`; thread A into `step`. This
is the paused r1 Slice A — re-target onto A-0's 32-bit-IR fetch (`FETCH_N=6*W`,
32-bit CNOT mask). **Gate:** `fetch_a ≡ fetch` at A=W (byte-identical);
`run_on_cpu == eval` for fib/lfsr/χ/sbox; `fetch_equiv`-style exhaustive fetch
correctness over all reachable PC; energy re-pin (step_j DROPS). *This slice pays
for itself and de-risks S1.*

## 8. Open questions

1. **Exact target B** (measurement in flight): gcd2 word body `peak_work=10`,
   `iter_len = |body|+10`, `k_max` from the trajectory walk. Pin B before choosing
   W_pc so the minimal-widening principle (§6) picks the smallest byte-multiple.
2. **W_br > 8?** Does any target program's δu (∝ iter_len / N_rom span) exceed
   255? A single short gcd2 loop keeps δu < 256 (W_br = 8, no BR widen — cheapest).
   Only multi-loop / long-ROM programs force the extra BR byte. Decide per the
   measured N_rom.
3. **imm widen vs two-Addi δu mint** (§3.4): widening `Instr::Addi{imm}` +
   `decode` is one localized change but touches the imm decode path (which the
   MAJOR-3 low-opcode-bits note, `asm.rs:331`, already flags as delicate); the
   two-Addi alternative avoids it at one instruction/loop cost. Reviewer decides.
4. **Append vs insert PC_hi** (r1 open Q): append keeps indices stable but makes
   PC non-contiguous in the bitstream. Confirmed no code assumes PC_lo/PC_hi
   adjacency (fetch/arith address by field index). Recommend **append** — but the
   adversarial review should re-break this (any `bits_of` consumer slicing a
   contiguous PC?).
5. **`me_a3` re-measurement OOM** (§6): the wider state inflates `lower_iso`
   intermediates; A-0 already peaks ~84 GB on a 94 GB box. Re-pinning at the wider
   state may not fit. Blocker unless the streaming `lower_iso` backlog item
   (`tisc2-roadmap.md:198`) lands first, or the golden is measured on a bigger box.
6. **Sequencing vs the roadmap.** The roadmap calls this **A-2** and puts it
